# 微信公众号情感文章生产

## 适用范围

当用户提供情感故事、树洞投稿、Telegram 内容、聊天截图或生活经历，并希望生成微信公众号文章、钩子标题、去 AI 味、风险检查或手机端 HTML 时使用本 Skill。

默认交付一篇约 900～1,200 字的情感文章；用户指定其他篇幅时服从用户。

## 核心原则

1. 事实边界优先。只使用素材中能确认的人物、动作、原话、时间、数字和结果，不补写未经提供的经历、对白、心理和结局。
2. 素材是案例，不等于文章主题。先从素材中找一个可讨论的情感问题，再让故事为这个问题服务。
3. 保留原素材的生活细节和口语感。文章可以更清楚，但不能改到失去原文特征。
4. 有钩子，不欺骗。标题可以制造好奇，但不能夸大、虚构或把普通矛盾包装成严重事件。
5. 风险检查用于降低误伤和违规概率，不用于规避平台审核，也不能保证推荐或不被限流。
6. 不直接模仿具体在世作者。可以使用高层次写法，例如情绪开场、短句推进、生活细节和克制观点，但不得复制独特句式或标志性表达。

## 完整流程

### 1. 提取素材

从文字、图片或截图中整理：

- 人物身份、年龄、关系和时间线
- 关键事件、生活细节和事件结果
- 原话、情绪、判断和疑问
- 看不清、矛盾或无法确认的内容

先区分事实、当事人观点、情绪表达和推测。看不清的内容标记为不确定，不凭上下文猜成事实。

### 2. 检查素材边界

Telegram、树洞和公开平台的内容仍可能涉及版权、隐私、名誉和投稿授权问题。不要整段照搬，不保留用户名、头像、手机号、聊天 ID、单位和可识别地点。改写不能替代授权。

素材不足时，选择以下一种处理：

- 能合理缩小主题，就缩短文章；
- 缺少关键事实且用户允许追问时，一次最多问 3 个问题；
- 不把模型临时想出的例子写成真实投稿。

### 3. 制作选题卡

在动笔前确定：

- 核心主题，用一句话写清；
- 目标读者和主要共鸣点；
- 素材是主故事还是案例；
- 作者最终要落到理解、分析还是建议；
- 文章不能越过的事实边界。

一篇文章只保留一个主问题，例如讨好型人格的自责、伴侣低能量时的沟通边界、分手后的放不下或婚姻中的孤独。

### 4. 设计文章结构

默认采用：具体细节开头 → 还原关键场景 → 提炼情绪问题 → 结合材料分析 → 给出现实建议 → 留有余味的结尾。

不强行套“3 个原因”或固定起承转合。每个段落都应带来新事实、新动作、新区别、新判断或新后果；只换说法重复上一段就删掉。

### 5. 完成初稿

写作时：

- 先让人物和动作出现，再补原因和背景；
- 多写吃饭、聊天、等待、沉默、删消息等可见细节；
- 允许“其实”“后来”“就”“也”“哎”等自然口气，但不主动添加粗口、错别字和网络梗；
- 长短句交替，普通段落普通结束；
- 不制造出轨、背叛、阴谋、报复和夸张反转；
- 不把单方投稿写成已经核实的客观结论；
- 建议要具体、克制，不替读者做人生决定。

### 6. 使用 human-writing 去 AI 味

若目标环境提供 `human-writing`，读取并执行它；需要进一步润色时可使用 `humanizer-zh`。重点检查：

- “不是……而是……”及同类翻案句；
- “真正的问题”“更深层次”“值得注意的是”等模板路标；
- 三项以上同构排比；
- 机械化的小标题和段落长度；
- 抽象名词、商业黑话和连续金句；
- 为了避免重复而强换同义词；
- 动作已经表达情绪后，又追加一层解释。

可以运行 `human-writing` 的 `check_prose.py`，但脚本警告需要结合语境人工判断。直接原话若命中禁用句式，改成转述或省略。

### 7. 生成钩子标题

正文完成并经过人味化后，再生成 5 个候选标题，覆盖：

1. 情绪共鸣型；
2. 问题提问型；
3. 生活细节型；
4. 关系洞察型；
5. 素材原话型。

最终给出 1 个首选标题和 2 个备用标题。标题应准确对应正文，有情绪、有问题或有具体场景，但不能使用虚假反转、恐吓、羞辱、绝对化群体判断或“震惊、看哭了、所有人都……”等低质表达。

标题检查项目：正文是否支撑、是否夸大、是否泄露隐私、是否含高风险词、是否适合手机阅读、是否存在标题与正文不一致。爆款无法保证，只能优化点击潜力和内容匹配度。

### 8. 内容与平台风险检查

检查露骨、血腥、违法、自伤、极端、仇恨、未成年人、隐私、诽谤和过度煽情表达。对情绪低落、失眠、易怒等内容，不做医学诊断，只建议在持续影响生活时寻求心理咨询师或医疗专业人员帮助。

必要时使用中性表达，并在投稿整理类文章末尾增加：

> 本文根据读者投稿及公开内容整理，人物信息已做模糊化处理。文中关于情绪状态的描述不构成医学诊断。

不要为了“过审”改变事实方向、删除必要语境或故意使用谐音规避审核。

### 9. 数字复检

明确的数值、日期、金额、比例、尺寸、重量和数据型次数使用阿拉伯数字，例如 `23岁`、`2025年`、`80元`、`3公里`、`75%`。

日常叙事、约数和固定表达使用中文数字，例如 `一个人`、`两个人`、`过了两天`、`七八天`、`一顿饭`、`两三次`、`三五个月`。

章节编号和排版导航可使用阿拉伯数字，例如 `01 · SELF-BLAME`。最终检查数字是否符合语境，不机械统一成一种写法。

### 10. 字数和事实复检

检查总字数、标题与正文一致性、人物指代、时间线、原话准确性、素材核心情绪、重复观点和虚构事实。文章已经讲完就停，不为了凑字数追加总结。

### 11. HTML 排版

默认使用舒缓的“留白禅意/奶油情感”方向：手机竖屏单栏、浅色背景、柔和灰绿或奶油色调、清晰段距、关键词加粗并改变颜色、重点句使用轻量引用框。不默认生成图片；用户明确要求漫画、配图或封面时再进入独立视觉流程。

若目标环境提供 `gzh-design`，读取其说明并运行 HTML 校验与预览脚本。干净 HTML 应使用内联样式，避免 `<style>`、`<script>`、`<div>`、`class`、`id`、横向布局和外部依赖；正文文字用 `span leaf` 包裹，以便复制到公众号编辑器。

### 12. 最终交付

默认输出：

- Markdown 文章稿；
- 干净版 HTML；
- 带复制按钮的预览 HTML；
- 首选标题和备用标题；
- 字数统计；
- 风险检查结果；
- 需要用户确认的模糊信息。

发布前提醒用户替换作者名、账号简介和来源说明。

## 常见错误

- 把 Telegram 原文简单换同义词后直接发布；
- 只围绕素材复述，没有清晰主题；
- 用假对白、假心理和假时间制造活人感；
- 标题比正文严重，靠夸张冲突吸引点击；
- 把“有风险”误写成“必然违规”；
- 把中文叙事里的“一两天、一个人”全部改成数字；
- 只做敏感词替换，不检查事实、隐私和版权；
- HTML 能看但不能复制到公众号；
- 没有运行文本检查、HTML 校验和移动端预览就声称完成。

## 默认执行口令

用户直接发送素材且未指定其他形式时，执行：

**提取素材 → 检查边界 → 确定主题 → 设计结构 → 写初稿 → human-writing 去 AI 味 → 生成并检查钩子标题 → 内容风险检查 → 数字和字数复检 → 手机端 HTML 排版 → 验证 → 输出文件。**
